# 作业 2：按要求打印 ASCII 小写字母

本题输出 ASCII 61H～7AH 的 a～z，共 26 个字母，分两行，每行 13 个字母。按题图在字母间加一个空格，行末不加空格：

```text
a b c d e f g h i j k l m
n o p q r s t u v w x y z
```

这里的“13 个字符”按题图理解为 13 个字母；分隔空格不计入字母数量。

## 1. 用 LOOP 指令实现

源码：`LOOP13.ASM`，可执行文件：`LOOP13.EXE`。

外层循环运行 2 次，内层循环运行 13 次。BL 保存当前字母，从 `'a'` 开始，每输出一个字母就 `INC BL`。DOS 的 `INT 21H`、AH=02H 服务输出 DL 中的字符。

关键结构如下；完整代码含输出空格、回车换行及退出：

```asm
    MOV BL,'a'
    MOV CX,2
ROW_LOOP:
    PUSH CX
    MOV CX,13
COL_LOOP:
    ; 输出 BL 中的字母，再 INC BL
    ; 非最后一列时输出空格
    LOOP COL_LOOP
    ; 输出 0DH、0AH
    POP CX
    LOOP ROW_LOOP
```

**为什么必须保存 CX？** 内外层 LOOP 都自动使用 CX。若直接把 CX 改成 13，外层计数就会丢失；内层结束时 CX=0。若此时直接执行外层 LOOP，CX 会从 0000H 减成 FFFFH，导致大量错误循环。`PUSH CX` 保存外层剩余次数，`POP CX` 在内层结束后恢复它。第一次外层计数 2→1，第二次 1→0，恰好输出两行。

LOOP 执行“CX 减 1，非零则跳转”，不依靠 ZF，也不会改变算术标志。本程序中的 `CMP CX,1 / JE` 仅用于控制最后一列不打印空格；两个循环本身均由 LOOP 控制。

程序没有数据段变量，字母和计数都放在寄存器里，02H 输出服务也不需要 DS:DX 字符串指针，所以无需像 Hello World 的 09H 服务那样初始化 DS。`.STACK 100H` 提供栈给 PUSH/POP 和中断使用。

## 2. 用条件跳转指令实现

源码：`JUMP13.ASM`，可执行文件：`JUMP13.EXE`。

SI 保存剩余行数，DI 保存当前行剩余列数，因此内外层计数不用共享 CX，也不用保存外层计数到栈。

```asm
    MOV BL,'a'
    MOV SI,2
ROW_NEXT:
    MOV DI,13
COL_NEXT:
    ; 输出字母、递增 BL，按需输出空格
    DEC DI
    JNZ COL_NEXT
    ; 输出回车换行
    DEC SI
    JNZ ROW_NEXT
```

`DEC DI` 根据减 1 的结果设置 ZF，`JNZ` 在 ZF=0 时跳回，即剩余列数不为零时继续。必须把 DEC 放在 JNZ 前，让跳转使用刚刚更新的计数结果。SI 的外层循环同理。源码中的 `JE` 与反汇编的 `JZ` 是同义指令。

本程序不含 LOOP 指令，确实用条件跳转完成循环。

## 3. C 实现与真实反汇编注释

C 源码：`ASCII13.c`。采用两层 for 循环，`row=0..1`、`col=0..12`，通过 putchar 输出字母、空格和换行。

当前电脑没有提供 16 位 DOS C 编译器。本次使用已安装的 **Cygwin GCC，x86-64，-O0** 编译并运行；所得 `ASCII13_C.exe` 依赖本机 Cygwin 运行库，应在 Windows 环境运行，不要放到 DOSBox 中执行。若课程额外要求 Turbo C 的 16 位反汇编，需要另用对应编译器重新生成，不能把本结果视为 8086 代码。

- `C_FULL_DISASM.txt`：从实际 C 可执行文件导出的完整反汇编，含源码对照和机器码。
- `C_MAIN_注释.txt`：main 函数的实际指令及逐条中文注释。
- `C_OUTPUT.TXT`：本次运行输出的两行字符。

可以观察到：未优化的 C 版本把 ch、row、col 放在栈中，循环变成 `CMP` 与 `JG/JLE`；不是源码写了 for 就必然生成 LOOP。RBP/RSP 管理 64 位栈，ECX 在这里传递 putchar 的整数参数，与 8086 程序中 CX 的循环计数用途不同。

## 如何运行与复现

双击 **运行实验.cmd**，在 DOSBox 中显示两个汇编程序的结果。双击 **重新验证.cmd**，重新汇编、链接、运行，检查精确输出及正常退出。工具统一放在仓库根目录 tools 中，配置方法见 tools/README.md。启动脚本挂载仓库根目录。

也可以在 DOSBox 的 `C:\HW2>` 下手动输入：

```dos
masm LOOP13.ASM,LOOP13.OBJ,LOOP13.LST;
link LOOP13.OBJ,LOOP13.EXE,LOOP13.MAP;
LOOP13
masm JUMP13.ASM,JUMP13.OBJ,JUMP13.LST;
link JUMP13.OBJ,JUMP13.EXE,JUMP13.MAP;
JUMP13
```

在 Windows PowerShell 中复现 C 编译与反汇编，工作目录为仓库根目录：

```powershell
& 'C:\cygwin64\bin\gcc.exe' -O0 -g -Wall -Wextra -std=c11 -o hw2/ASCII13_C.exe hw2/ASCII13.c
& ./hw2/ASCII13_C.exe
& 'C:\cygwin64\bin\objdump.exe' -d -S -Mintel hw2/ASCII13_C.exe
```

## 验证结果

两份 DOS 汇编程序都完成真实汇编、链接和执行，MASM 结果均为 0 警告、0 严重错误。输出文件 `LOOP13.TXT`、`JUMP13.TXT` 已逐字符核对，恰好两行、字母顺序 a～z、每行 13 个字母，无行末空格。DEBUG 日志 `LOOPDIS.LOG`、`JUMPDIS.LOG` 包含实际反汇编与正常退出码 0000。

C 版本使用 `-Wall -Wextra` 编译，无诊断输出，实际运行的两行文字与汇编版本相同。反汇编注释依据本次可执行文件中的 main 函数编写，未将手写伪汇编冒充编译器输出。
