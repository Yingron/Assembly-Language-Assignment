## 二、课堂练习：进制转换

### H2D.ASM：1～2 位十六进制转十进制

支持 `0`～`FF`，字母大小写均可，不带 0x 前缀。例：输入 `ff`，输出 `255`；输入 `a`，输出 `10`；输入 `00`，输出 `0`。

读取每个字符，先把 ASCII 字符变为数值 0～15，再用 **当前值 = 当前值 × 16 + 新数位** 累积。例如 FF：第一次得到 15，第二次得到 15×16+15=255。

字符转换：`'0'～'9'` 减 `'0'`；`'A'～'F'` 减 `'A'` 再加 10；小写先转为大写。程序会检查合法字符及长度，`G`、空输入、`100` 等返回 `Invalid input.`，退出状态为 1。

### D2H.ASM：十进制转十六进制

这项对应图片的追加要求。本实现选择与 H2D 相同的数值范围 **0～255**，最多 3 位十进制字符；不接受正负号和空格。例：255→FF，16→10，10→A，0→0。输出使用大写字母，不补前导零。

十进制输入按 **当前值 = 当前值 × 10 + 新数位** 累积。输出时使用 `DIV BL`，BL=16，被除数 AX≤255：AL 得商（高位），AH 得余数（低位）。AH 中的低位先存入 BH，防止输出中断设置 AH 后将其覆盖。高位是 0 时省略，低位总会输出。

## 三、作业基本要求：1+2+…+100

三份程序都真正循环累加，不是直接打印常量 5050：

- **SUMREG.ASM**：AX 保存累加和，BX 从 1 递增到 100，CX 控制循环次数。
- **SUMMEM.ASM**：数据段的 `Total dw 0` 保存累加和，使用 `ADD Total,BX` 在每轮更新数据段变量。
- **SUMSTK.ASM**：建立 BP 栈帧并分配 2 字节局部变量，用 `ADD WORD PTR [BP-2],BX` 在每轮更新栈中的累加和。BP 寻址默认使用 SS，因此这里确实操作栈段。循环结束后释放局部空间并恢复 BP。

三者运行结果均为：

```text
5050
```

**表示范围**：5050=13BAH，超过 8 位无符号数上限 255，所以必须使用至少 16 位。16 位无符号数上限为 65535，足以保存本题结果。不要把结果只放进 AL 或 BL。

**打印十进制**：所有程序共用 IO.INC 中的 PrintDec。将 AX 反复除以 10，把每次余数压栈，最后依次出栈，加 ASCII `'0'` 后输出。5050 的余数依次为 0、5、0、5，反向弹出就是字符 5、0、5、0。

每次 `DIV BX` 前必须 `XOR DX,DX`，因为 16 位除法实际计算的是 DX:AX÷BX；AX 是商，DX 是余数。PrintDec 使用“至少执行一次”的循环，因此 0 也能正确输出。它保存并恢复 AX、BX、CX、DX，内部压栈与弹栈数量对应。

## 四、用户输入扩展

**SUMIN.ASM** 将题图“用户输入 1～100 内的任何一个数”解释为：输入 n，计算并输出 **1+2+…+n**。这是结合求和题上下文采用的解释；题图没有明确写出扩展后的求和上限表达式。

例：1→1，10→55，100→5050。`0`、`101`、负数、字母和空输入会报错。允许范围内的前导零，例如 `001`→1。

输入使用 DOS `INT 21H` 的 **AH=0AH 缓冲行输入**：

- DS:DX 指向 InBuf。
- 第 0 字节为缓冲区容量，本实现设为 81。
- 第 1 字节是实际输入字符数，不含回车。
- 第 2 字节起存字符，输入末尾的回车不参加转换。

ReadNumber 按字符检查并转换，成功返回 AX 和 CF=0，失败返回 CF=1。调用方先检查 CF，避免拿错误输入参与计算。空输入和长度超过本题限制的输入会报错。交互输入超过缓冲区容量时由 DOS 行编辑服务限制继续录入。

其他中断功能：AH=09H 输出 DS:DX 指向的 `$` 结尾字符串；AH=02H 输出 DL 中的单个字符；AH=4CH 退出程序，AL 是返回状态。`.MODEL SMALL` 程序入口先设置 DS，使数据段字符串和输入缓冲区可正确访问。

## 五、C 实现与反汇编

**SUM.C** 默认计算 1～100，使用 for 循环累加并用 `%u` 输出。也支持命令行参数，例如在 Windows 中运行 `SUM_C.exe 10` 得到 55。无参数运行得到 5050。

**C_SUM_注释.txt** 是实际编译所得 sum_to 函数的逐条中文注释，包含指令地址和机器码；**C_FULL_DISASM.txt** 保留带源码的完整反汇编。

此处使用本机 **Cygwin GCC、x86-64、-O0**，所得 EXE 是 Windows/Cygwin 程序，需本机 Cygwin 运行库；它不是 DOS 可执行文件，不能在 DOSBox 中运行。它的反汇编也不是 8086 代码。若老师要求 16 位 C 编译器的反汇编，需要再用对应编译器生成；本题图片未限定 C 编译器。

可观察到：total 放在 `[RBP-4]`，i 放在 `[RBP-8]`，循环由 CMP/JAE 控制；C 的 for 不必编译成 LOOP。当前编译器的 unsigned int 是 32 位，而手写 8086 版本用 16 位字。注释中的 RBP、EAX、ECX 不能直接照抄到 8086 程序。

在 PowerShell 中复现：

```powershell
.\Build-C.ps1
```

脚本明确使用 `-x c`，避免大写 `.C` 扩展名被 GCC 当成 C++。它重新编译、生成反汇编、检查默认输出及 1～100 的全部输入，再从真实反汇编提取注释。
