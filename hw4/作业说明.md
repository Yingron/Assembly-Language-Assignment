# 作业 4：乘法指令和过程调用

按两张题图完成两项 8086/DOS 汇编程序，使用 `MUL`、双重 `LOOP` 和 `CALL/RET`，并提供两项任务的 C 实现、真实反汇编和中文逐条注释。

## 一、文件及运行方法

- `MUL9.ASM/EXE`：按 9～1 行输出倒三角九九乘法表。
- `CHECK9.ASM/EXE`：检查题图给出的完整 9×9 数据，输出错误行列坐标。
- `IO.INC`：两份汇编程序共用的输出过程，重新汇编时必须与源码一同保留。
- `HW4.C`、`HW4_C.exe`：C 版本，依次输出乘法表、全局数组检查和局部数组检查。
- `C_FULL_DISASM.txt`：本次 C 可执行文件的完整反汇编，含源码、地址和机器码。
- `C_HW4_注释.txt`：六个 C 函数的实际反汇编及逐条中文注释，包含全局/局部数组的寻址对比。

汇编环境沿用前三次作业：DOSBox 0.74、MASM 5.10、LINK 3.65。按仓库根目录 README 挂载仓库与工具目录后，在 DOSBox 中执行：

```dos

cd \HW4
MUL9
CHECK9
```

重新编译（当前目录须有 `IO.INC`，MASM、LINK 已配置到 PATH）：

```dos
masm MUL9.ASM,MUL9.OBJ,MUL9.LST;
link MUL9.OBJ,MUL9.EXE,MUL9.MAP;
masm CHECK9.ASM,CHECK9.OBJ,CHECK9.LST;
link CHECK9.OBJ,CHECK9.EXE,CHECK9.MAP;
```

C 程序在 Windows 的 Cygwin 环境运行，依赖 Cygwin 运行库，不能在 DOSBox 中运行。可在本目录的 PowerShell 中编译、运行并查看反汇编：

```powershell
& 'C:\cygwin64\bin\gcc.exe' -x c -O0 -g -Wall -Wextra -Werror -std=c11 -o HW4_C.exe HW4.C
& .\HW4_C.exe
```

`-x c` 明确指定 C 语言，避免大写 `.C` 被 GCC 当作 C++。本次 C 反汇编为 **x86-64**，手写汇编为 **8086**，与前三次作业采用的环境一致；题图没有指定 C 编译器。若课堂另要求 16 位 C 反汇编，应使用对应编译器重新生成，不能把本文件当作 8086 代码。

## 二、输出九九乘法表

输出与题图一致：行号从 9 递减到 1，每行列号从 1 递增到行号，共输出 45 项；每项占 8 列，兼容 80 列 DOS 文本屏幕。

```text
The 9mul9 table:
9*1=9   9*2=18  9*3=27  9*4=36  9*5=45  9*6=54  9*7=63  9*8=72  9*9=81
8*1=8   8*2=16  8*3=24  8*4=32  8*5=40  8*6=48  8*7=56  8*8=64
7*1=7   7*2=14  7*3=21  7*4=28  7*5=35  7*6=42  7*7=49
6*1=6   6*2=12  6*3=18  6*4=24  6*5=30  6*6=36
5*1=5   5*2=10  5*3=15  5*4=20  5*5=25
4*1=4   4*2=8   4*3=12  4*4=16
3*1=3   3*2=6   3*3=9
2*1=2   2*2=4
1*1=1
```

主程序用 `BH` 保存行号、`BL` 保存列号，`CX` 控制 `LOOP`。进入每一行时，先 `PUSH CX` 保存外层循环次数，再让 `CX=BH` 控制本行项数；本行完成后 `POP CX` 恢复外层次数。因此内外两层循环共用 CX 也不会相互破坏。

`CALL PrintProduct` 输出一项，其内部执行：

```asm
mov al,bh
mul bl       ; 无符号 AL*BL，16 位结果存入 AX
call PrintDec
```

8 位乘法的隐含被乘数为 AL，结果为 AX；不能把乘法结果理解为仍只存在 AL。这里最大结果 9×9=81，虽然 AL 足够保存，本程序仍将完整 AX 传入十进制输出过程。

`PrintProduct` 还要借用主程序正在使用的 `CX` 输出间隔，所以过程入口依次保存 AX、BX、CX、DX，返回前按相反顺序恢复。它实际使用并保护了主程序的寄存器资源，调用后行号、列号、循环次数均有效。

## 三、九九乘法表纠错

`CHECK9.ASM` 的 81 个字节与题图逐项一致，包括五个故意填为 7 的错误。程序扫描完整 9×9 矩阵，每格都计算正确乘积并比较，输出从 **1 开始** 的坐标，`x` 为行、`y` 为列。

```text
x y
1 1  error
2 3  error
4 5  error
6 6  error
8 8  error

accomplish!
```

五处错误及正确值：

- (1,1)：存储值 7，正确值 1。
- (2,3)：存储值 7，正确值 6。
- (4,5)：存储值 7，正确值 20。
- (6,6)：存储值 7，正确值 36。
- (8,8)：存储值 7，正确值 64。

程序按题目基本要求定位并显示错误，保留原表，便于重复检查。它依据每格实际值判断，因此表中其他位置的合法值 7 不会误报。

**数据段寻址**：`Table` 用 `DB` 定义，元素占 1 字节，按行连续存放。坐标 (x,y) 对应偏移 `(x-1)*9+(y-1)`；例如 (4,5) 对应偏移 31。入口先设置 DS，再用 `MOV SI,OFFSET Table` 取得首地址；每检查一格只执行一次 `INC SI`，从首字节连续扫描到偏移 80。

```asm
mov al,bh
mul bl
cmp al,[si]  ; [SI] 默认在 DS 段，AL 决定这是字节比较
je CellOK
call ReportError
```

这里 BH、BL 为从 1 开始的行列号。外层、内层均循环 9 次。`ReportError` 借用 CX 输出两个空格，先压栈保存 CX，返回时恢复；SI 不被该过程修改。这样连续遇到多个错误时，仍能继续遍历正确位置。

## 四、过程调用、保存恢复与输出

本次过程均为同一代码段内的近调用。8086 的近 `CALL` 将下一条指令的 IP 压入栈，再转入被调用过程；近 `RET` 从栈中弹出 IP，回到调用处继续执行。`CALL/RET` 不会自动保存通用寄存器，过程必须按约定自行保存需要保护的寄存器。所有保存与恢复都按后进先出配对，不能用 `POP` 顺序与 `PUSH` 顺序相同的方式恢复多个寄存器。

两份程序使用 `.STACK 100h` 建立栈。两层 LOOP 之间的 `PUSH CX/POP CX` 保护外层计数，过程入口/出口的保存恢复保护调用方状态，这两种保存用途不同。

`IO.INC` 中：

- `PrintChar`：DL 传入字符，使用 DOS `INT 21H/AH=02H`，保护 AX、DX。
- `PrintString`：DS:DX 指向以 `$` 结束的字符串，使用 `AH=09H`，保护 AX、DX。
- `NewLine`：依次输出 CR=13、LF=10，并恢复 DX；调用的 `PrintChar` 保护 AX。
- `PrintDec`：AX 传入无符号整数，重复除以 10，将余数压栈，再反向弹出并转为 ASCII 输出；保护 AX、BX、CX、DX，也能输出 0。

16 位 `DIV BX` 的被除数是 **DX:AX**，商在 AX，余数在 DX，所以每次除法前必须 `XOR DX,DX`。例如 81 先得到余数 1，再得到余数 8，逆序弹出就是字符 `8`、`1`。

这些过程没有承诺保存 FLAGS。主程序在 `CMP` 后立即使用 `JE`，没有跨过程调用依赖旧标志位。程序结束使用 `INT 21H/AH=4CH`，AL=0 表示完成检查；发现表内错误属于正常业务输出。

## 五、C 语言及真实反汇编观察

`print_table` 实现相同双重循环，调用 `print_product` 计算并输出各项；`check_global` 和 `check_local` 对完全相同的数据执行相同的 9×9 检查，都输出上面五处错误，并返回错误数量 5。`main` 正常完成后返回 0。

本次使用 `-O0 -g` 保留容易对应源码的循环与局部变量。`C_HW4_注释.txt` 对六个函数的实际指令逐条解释，包括以下关键位置：

- `print_product` 的 `0x100401091` 为 `IMUL EAX,[RBP+0x18]`，计算 row×column。C 中 int 是有符号 32 位；8086 手写版本使用 8 位无符号 MUL，本题输入都是正数，结果相同。
- `print_table` 的 row 在 `[RBP-4]`，column 在 `[RBP-8]`；循环由 CMP、JLE、JG 控制。C 的 for 不必编译为 LOOP。
- `check_global` 在 `0x100401192` 用 RIP 相对 LEA 取得 `global_table` 地址 `0x100402020`，再加上 `row*9+column`。本次全局可写数组位于 `.data`，具有静态存储期，在整个程序执行期间存在。
- `check_local` 入口分配 128 字节栈空间，并将 81 个数组初值写入 `[RBP-0x60]` 起的连续空间；读取时计算 `RBP-0x60+row*9+column`。每次调用都初始化该自动数组，返回后其生命周期结束。
- 两份检查代码都通过“左移 3 位再加 row”形成 `row*9` 的字节偏移，再用 IMUL 计算正确乘积。寻址计算和业务乘法不必使用相同指令。
- `check_local` 的 `ADD RSP,0xffffffffffffff80` 等价于减去 128，尾部 `SUB RSP,0xffffffffffffff80` 等价于加回 128。不要只看 ADD/SUB 助记符就误判栈空间的申请与释放。

上述地址只对应本次实际构建，修改代码或编译选项后可能改变。全局/局部描述作用域，存储期还与声明方式有关：局部 `static` 数组也具有静态存储期，不能概括为“所有局部数组都放在栈上”。这里的栈布局是本次编译所得结果，不是 C 语言对所有实现的强制规定。
